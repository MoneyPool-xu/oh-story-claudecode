# 检查失效与返工规则

## 判断原则

检查结论绑定输入版本、章节范围、平台和规则日期。任一绑定项变化时，按实际影响标记 `STALE`，不要把全部检查一刀切重跑。

## 变化到重检的映射

| 变化 | 必须重跑 | 通常不受影响 |
|---|---|---|
| 只修错别字、标点 | 中文终校；若已做平台门禁则平台门禁 | 原创性、结构审查 |
| 改写句段、对白、叙述 | 受影响场景的自然成稿复检；若写作任务或笔墨重心改变则重建章卡；文风漂移、去AI味、中文终校、平台门禁 | 未受影响章节的结构结论 |
| 调整场景顺序、章末钩子 | 读者盲读、综合审查、去AI味、终校、平台门禁 | 已登记来源本身 |
| 改人物动机、事实、伏笔 | 写作追踪事务、自然成稿重建、读者盲读、综合审查及所有后置门禁 | 市场扫描 |
| 引入或更换参考作品 | 原创性审计；若影响正文则所有对应后置检查 | 已完成的纯数据口径检查 |
| 新增、更换或重做本章拆文手法卡 | 本章自然成稿指令卡标记 `STALE` 并重建；若正文已写则复检文风、原创性和去AI味 | 未引用该手法卡的章节 |
| 更换书名、简介、标签 | 对这些发布物料做盲读、终校、平台门禁 | 正文章节审查 |
| 更换目标平台 | 新平台合规检查；重新确认篇幅和格式 | 中文终校（文本未变时） |
| 改变视角人物、场景主任务或读者理解门槛 | 自然成稿重建；若正文已写则重跑文风、盲读、去AI味和终校 | 原创性来源登记 |
| 修改对应细纲、项目文风或本章主要角色声纹 | 本章自然成稿指令卡标记 `STALE` 并重建；正文已写则从写作修订向后重跑 | 无关章节的指令卡与门禁 |
| 平台规则更新 | 平台门禁 | 文风、原创性 |
| 发布后正文重发/改章 | 数据诊断重新分批，并重跑改动对应门禁 | 改动前历史数据（保留为旧批次） |

## 版本标识

优先使用 Git commit；无 Git 时记录文件路径、修改时间和大小。多文件范围生成清单，不要求使用不可复核的“最终版”“最新版”等标签。

## 闭环顺序

1. 记录触发变化及受影响范围。
2. 把受影响检查标记为 `STALE`。
3. 若变化触发章卡失效，先重建并校验《第XXX章自然成稿指令卡》，再完成会继续改变正文的修订。
4. 从最早受影响节点向后重跑。
5. 保存新报告并保留旧报告；在新交接单中链接取代关系。
