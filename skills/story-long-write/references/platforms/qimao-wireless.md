# 七猫无线文平台适配

仅在项目明确目标平台为“七猫”时加载。它是前期命中风险诊断，不是固定字数、固定桥段或爽点次数公式；具体判断应结合当前日期的同平台、同赛道样本。

## 七项诊断

| 指标 | 要问的问题 | 高风险信号 |
|---|---|---|
| Promise Visibility | 书名、简介、标签承诺的差异化卖点，前三章是否已可感知？ | 只讲背景，核心能力、关系命题或独特困局迟迟不可见 |
| Protagonist Agency | 主角是否主动决定并改变局面？ | 连续承受、等待别人救场或被剧情推着走 |
| Conflict Consequence | 冲突是否改变状态？ | 争吵、羞辱、威胁结束后身份、关系、资源、风险、目标均未变化 |
| Payoff Quality | 兑现是否包含压力、主动行为、可见结果和后果？ | 只说狠话、反派脸白、旁观者震惊，现实状态不变 |
| Cognitive Load | 前三章认知负担是否服务当前问题？ | 新人物、关系、设定、时间线先于人物问题密集出现 |
| Antagonist Credibility | 阻力为何仍有效？ | 反派只靠降智续命，或被打败后无资源、制度和关系后盾却继续阻碍 |
| Prose Friction | 语言是否拖慢读者抵达行动与结果？ | 重复解释、无效心理、套话、无功能微动作和段尾金句密集 |

## 黄金三章风险检查

- 第一章：差异化卖点可感知；形成“危机/缺口 → 核心优势被获得或利用 → 主动选择 → 局面变化”的小闭环。情感文的优势可以是认知与行动转向，不强制金手指或打脸。
- 第二章：扩大问题、代价或关系，不复制第一章的同类兑现。
- 第三章：让故事具备可滚动性，出现新的目标、关系变化或更大冲突，并留下具体下一问。

这三条是功能检查，不是章序模板。必要功能可以跨章分布，但前三章结束时应让卖点、主角行动和至少一次有效兑现可见。

## Attention Continuity

平台不排斥所有慢，只警惕无期待的慢。对较长铺垫逐段问：读者正在等什么？本段新增了什么证据、部分支付、关系变化、风险或选择？无法回答时标高风险；不要用“每 800 字反击”“每 1500 字觉醒”等数字替代判断。

## 写作交接

传给正文 Writer 的 `platform_constraints` 只保留本章相关的 3–7 条功能要求，例如“本章结束前让核心能力产生一次可见结果”。不得传入固定字数爆点、固定角色救场、统一短句或“所有人震惊”等表达模板。
