# 单章商业价值开工门禁

仅在项目目标平台明确为七猫/无线买量，或用户主动启用时执行。它防止没有状态变化、没有主角行动、没有支付、没有下一问的空转章；不要求每章都打脸、亮金手指或获得实物。

## 六维对账

1. `state_change`：本章结束后，风险、信息、关系、资源、身份、目标、决定或行动方向发生什么不可轻易复原的变化？
2. `core_advantage`：主角的核心优势本章是显性展示、隐性运用、受限、付出代价，还是本章不适用？`not_applicable` 合法，但须说明章节功能。
3. `contested_value`：角色正在争夺、保护或改变什么具体对象、权益、关系位置、信息控制权或行动机会？不限实物。
4. `visible_gain_or_payment`：读者在本章得到什么可见支付——实物/账目、地位、关系、信息、能力进展、风险解除、部分兑现或失败补偿？
5. `next_question`：章尾留下哪个可用一句话回答的具体下一问？动力类型是行动、风险、选择、信息、关系或兑现后果中的哪一种？
6. `protagonist_action`：推进主要来自谁的决定与行动？环境、心理和日常描写具体服务什么变化？

## 组合判定

- `state_change` 与 `protagonist_action` 必须有具体证据。
- `visible_gain_or_payment` 至少一种成立；低压/关系/侦查章允许部分支付或失败补偿，不硬造实物收益。
- `next_question` 必须具体；“回房休息”“以后再说”“新的风暴将至”等完成性收束或抽象预告不算。
- `core_advantage` 与 `contested_value` 可以 `not_applicable`，但两项不能同时用空话绕过，且本章仍须满足前三条。

输出 `audit_logs/chapter_{N}_gate.json`，包含 `schema_version: 1`、章号、细纲相对路径、细纲 SHA-256、章节定位、六维证据、`decision: PASS|BLOCK` 与 `blockers`。任何细纲改动都会令旧 JSON 失效。Agent 负责语义判断，Hook 只校验版本和决定，不在本地假装预测真实流失率。
