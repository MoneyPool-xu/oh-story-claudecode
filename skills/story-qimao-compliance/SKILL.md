# story-qimao-compliance：七猫投稿合规门禁

把七猫平台红线、女频签约标准、赛道匹配和商业网文质量串成一次可执行的投稿前检查。不承诺"必过签"，但覆盖已知的高频退稿原因。

## 七猫平台特征

七猫是免费阅读平台，核心商业模式是广告变现。与番茄类似但有以下差异：

- **签约制**：需要编辑审核通过后签约，不是自由发布。投稿材料通常包括前三章正文 + 简介 + 大纲。
- **女频主流赛道**：现言总裁、古言宅斗。权谋/军事/女将军题材在女频签约率极低。
- **编辑偏好**：快节奏、强爽感、金手指可见、CP前置、前三章定生死。
- **读者画像**：20-35岁女性，碎片化阅读，对前3章要求极高，乐于为爽点和情感互动付费。

## 选择工作模式

1. **投稿前审查**：检查前三章正文、简介、大纲和投稿附言，输出证据、分级和结论。
2. **退稿诊断**：读取编辑返回的拒绝理由（如有），结合赛道和内容做根因分析。无具体理由时只列候选风险。
3. **写作前约束**：把七猫签约标准写入项目参考资料，给大纲/章节增加风险边界。
4. **合规修订**：保留剧情功能，改掉风险表达、节奏问题和赛道偏移；修改后完整复查。

未要求改稿时只审查，不改文件。

## 定位 story 项目

1. 先解析用户点名的受检文件，再判断是否属于当前 story 项目。
2. 仅当受检文件位于书目录内时，从当前目录定位项目根。
3. 读取设定、大纲、细纲和已有正文作为上下文。
4. 已绑定项目且存在项目自有平台规范时优先读取；否则读取本 skill 的 `references/qimao-policy.md`。

## 与 story skills 衔接

- 长篇写作或修改：先按 `story-long-write` 完成正文，再执行本门禁。
- 去AI味：先修平台风险和节奏问题，再用 `story-deslop`；去味后重新运行本门禁。
- 综合审查：本门禁给出七猫专项风险后，再用 `story-review` 做完整审查。
- 用户只要求审查时，不自动续写、不修改大纲、不推进追踪。

## 执行五道门禁

完整判定项和边界读取 `references/qimao-policy.md`，报告格式读取 `references/review-rubric.md`。

### 1. 平台硬红线

与番茄一致的内容底线：法律政策、恐怖极端、民族宗教、淫秽色情、赌博吸毒、犯罪教学、未成年人不当内容、隐私侵权。虚构灵异和战斗不自动违规；判断是否现实可复现、是否宣扬、是否过度渲染。

### 2. 赛道匹配（七猫特有）

这是四次退稿的首要教训。检查：

- 题材标签是否落在七猫女频验证过的赛道（现言总裁 / 古言宅斗 / 重生 / 甜宠）。
- 是否踩入权谋、军事、女将军、朝堂布局等七猫女频零上榜赛道。
- 宅斗是否真的在写"内宅博弈"（嫡庶之争、婆媳矛盾、管家夺权），还是滑向了朝堂权谋。
- 金手指是否通过"后宅手段"实现（联姻、管家、经商、医毒），而非通过"朝堂布局"。
- 简介和标签是否明确标注赛道，不让编辑误判方向。

### 3. 黄金三章节奏（七猫签约核心）

编辑看前三章决定签不签。逐章检查：

**第一章：**
- 是否在前500字内建立核心冲突或重大异常。
- 重生/穿越是否在第一章完成（不拖到第二章）。
- 金手指是否在第一章末尾出现激活信号。
- 心理描写是否控制在500字以内。
- 背景交代是否控制在300字以内。
- 章尾是否有明确钩子。

**第二章：**
- 金手指是否有"看得见"的首次展示（具象技能释放、当场打脸、可视化爽点）。
- 是否有第一次反击/翻盘。
- 女主是否展现出不同于前世的主动性。

**第三章：**
- 是否完成首次打脸（让读者爽到）。
- CP互动是否有实质推进（不是远远看一眼）。
- 是否建立了"继续追下去"的三重悬念。
- 男主是否正式出场且有令人印象深刻的互动。

**整体三章节奏：**
- 每章是否有独立冲突和小高潮。
- 对话是否短、动作是否快、打脸是否狠。
- 情绪曲线是否有起伏（压抑→爆发→期待）。

### 4. CP前置与金手指可见性（七猫签约高频退稿点）

**CP线：**
- 男主是否在前10章正式出场。
- 前三章是否有男主与女主的实质互动（不是远远看一眼）。
- 互动是否产生了"他知道什么""他为什么帮她"的好奇心。
- CP双向吸引信号是否可见（哪怕是单方面的暗中关注）。

**金手指：**
- 金手指是否"看得见"——有具象的技能释放、物品变化、知识涌入。
- 是否在前三章让读者明确理解"这个金手指怎么用、能干什么"。
- 金手指使用是否产生即时可见效果（当场解决问题/当场打脸）。
- 不能只是"心中有了计较""布局""权谋分析"等抽象操作。

### 5. 低质与水文

与番茄一致的质量底线，加上七猫特有的节奏要求：

- 无重复段落、模板化章节、符号乱码、百科拼贴。
- 无超过500字的连续心理描写。
- 无超过300字的连续背景/环境描写。
- 无流水账（起床→洗脸→吃饭→出门式叙述）。
- 转折有因果，人物出场有铺垫。
- 每章至少有明确目标、关键行动、可见结果和翻页推动力。

## 运行静态预检

```bash
python3 <skill-dir>/scripts/qimao_preflight.py <file-or-directory> [more paths]
```

需要机器可读结果时加 `--json`。脚本检测重复段落、工程词、乱码行、引流表达和七猫特有的节奏指标（心理描写长度、背景描写长度、对话密度、金手指/CP关键词出现位置）。

## 分级和处置

- **BLOCK**：平台红线、赛道严重偏移（写成权谋/军事）、正文垃圾行、重复填充。
- **FIX**：三章节奏不达标、金手指不可见、CP缺失、水文、突兀转折。具体改法并复查。
- **REVIEW**：灵异/暴力边界、赛道模糊地带、编辑主观偏好区域。标出证据交人工确认。
- **PASS**：本次范围未发现已定义风险。不等于编辑保证签约。

## 完成交付

报告必须包含：检查范围、总结果、五道门禁逐项结论、BLOCK/FIX/REVIEW证据、简介和附言检查、已修改文件、未修改项、脚本结果和仍需人工确认的边界。

特别要回答：**如果你是七猫编辑，看到这三章会签吗？最可能的拒绝理由是什么？**
