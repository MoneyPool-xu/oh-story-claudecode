# 读者动力机制与 Skill 提炼

本文件是 `story-long-analyze` Stage 4-5 的权威方法。Stage 2 只回答「发生了什么」，Stage 3 只组织事实；本文件回答「读者为什么继续」和「哪些机制值得学习」。三层结论不得互相倒灌。

## 数据边界

- Stage 4 默认只读 Stage 2-3 的章节摘要、情节点、剧情单元、故事线、角色与设定；不得重读整本原文。
- 只有证据冲突或关键事实缺失时，才按章节定位回查最小原文片段，并记录回查范围。
- 机制判断必须带章节、情节点或剧情单元来源；证据不足写「待验证」，不能补成事实。
- Stage 5 只读 Stage 4 机制文件和 Stage 3 事实索引，不得从一句漂亮话、单个桥段或频率统计直接制造通用规则。

## Stage 4：Narrative Mechanism

站在第一次阅读的读者位置，按自然剧情单元与卷级尺度分析，不模仿作者、不替成功作品合理化缺陷。

### `剧情/读者契约.md`

每个剧情单元记录：章节范围、进入时问题、当前许诺、预期回报、延迟答案、部分支付、正式兑现、替代问题、章尾翻页动力、证据。章尾动力分为信息、危机、决策、人物、身份、兑现前停顿、结果反转。频率只作观察，不作配额。

### `剧情/期待债.md`

每条债记录：ID、类型、建立处、许诺、读者期待、当前状态、部分支付、最终兑现、转化去向、证据。类型可含身份、复仇、实力、真相、感情、重逢、承诺、宝物、身世、危机。只有正文已让读者明确等待结果时才登记；普通伏笔不自动算债。

### `剧情/情绪债.md`

每条记录：来源、对象、触发、积累、升级、目标情绪、机制、兑现、余波、证据。不能只写「爽/虐/甜」；必须解释来源，例如「长期低估 → 公开验证 → 群体认知翻转」。

### `剧情/关系债.md`

对重要关系记录：人物、与主角关系、初始需要、未决事项、分离原因、未完成行动、情感不对称、最后状态、读者问题、未来回报、证据。关注角色离场后为何仍被记住。

### `剧情/成长与升级.md`

同时记录：

- 主角代理权：当前目标、谁定义目标、可选方案、主动选择、代价、后果、下一目标。
- 升级重新定价：旧状态、新能力、新可解问题、新可见问题、旧优势重估、保留资产、新限制。
- 地图扩张：进入理由、保留关系/资产/债务、新规则、新威胁、新机会、连续性桥梁。
- 失败补偿：损失、责任、保留资产、新信息、新方向、给读者的补偿。
- 兑现结构：许诺、压力、延迟、部分支付、主角行动、正式兑现、见证者、后果、新问题。

核心判断不是「赢了几次」，而是压力与等待如何经主角行动得到可感知回报。重要失败应分析它提供了什么继续阅读补偿，以及是否带来明显劝退成本；不得因作品整体成功就默认该次失败没有流失读者。

## Stage 5：Skill Extraction

输出目录 `提炼/`：

- `通用候选规则.md`：Core Universal 候选。
- `题材规律.md`：Genre Pattern，只在相应题材启用。
- `作者特征.md`：Author Signature，仅供理解，不进入通用 Skill。
- `有效但高风险.md`：Effective But Risky，写明短期收益、长期成本、适用与禁用场景。
- `反模式.md`：Problem / Anti-pattern，写明读者成本、结构原因与规避规则。

每条规则必须包含：名称、原始观察、抽象规则、作用机制、适用范围、证据书目、`evidence_refs`、证据等级、`counterexample`、`failure_condition`、失败模式、使用边界，以及 `writer_visibility` / `planner_visibility` / `reviewer_visibility`。不要让 Writer 持有只适合规划或审查的元规则。

```yaml
skill_candidate:
  name:
  source_observation:
  abstract_rule:
  mechanism:
  scope:
  evidence_books: []
  evidence_refs:
    - 第12章/P4
    - 第18章/P7
    - 剧情单元：宗门试炼
  evidence_level: L1
  counterexample: []
  failure_condition: []
  failure_mode:
  boundary:
  writer_visibility:
  planner_visibility:
  reviewer_visibility:
```

`counterexample` 记录不符合该规律仍然有效的样本，用来限制过度概括；`failure_condition` 记录该机制在什么条件下失效。`evidence_refs` 必须指向可重新定位的章节/情节点或剧情单元，不能只写抽象印象。

### 验证等级

| 等级 | 条件 | 允许状态 |
|---|---|---|
| L1 | 单书发现 | Observation，只能进入候选文件 |
| L2 | 至少 3 本不同作者作品重复出现 | Candidate Pattern |
| L3 | 跨至少 2 个题材仍成立 | Universal Principle，可建议进入 Narrative Kernel |

单书成功不能证明因果。不得把「平均每三章一个爽点」「短句占比高」等相关性直接写成生成规则；应抽象为读者耐心耗尽前的部分回报或状态变化。

### 跨书验证入口

默认全流程自动执行 Stage 4-5。高级入口只用于：已有旧拆文结果补跑机制层、或比较多本已拆作品。补跑前校验 Stage 2-3 事实产物齐全；跨书时读取各书 `提炼/` 与机制文件，更新证据等级，不重跑 Stage 0-3，不覆盖单书观察。

## 质量门

1. 每个机制结论至少有一个可定位证据；跨章机制至少有建立与支付两端证据。
2. `发生了什么`、`为什么有效`、`是否可迁移`分别落在事实层、机制层、归纳层。
3. 所有发现必须进入五类之一，不允许含混地写成「可借鉴」。
4. 总报告必须同时呈现有效机制、有效但有代价、作者特征和明显问题，禁止吹书式总结。
